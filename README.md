# Mirror 21 · light app design handoff

Everything you need to build the light iPhone version of the course in VS Code.

```
Mirror21/
├── index.html     opens Sign in (the Offer page is hidden for now)
├── src/           the pages' sources: edit these, then run node tools/build.js
│   ├── steps/stepNN/     everything about one step: learn.html, act.html (its pages) and step.js (its title,
│   │                     video length, examples, block skill, how its promise is built, its journal lines)
│   ├── pages/            the other pages' sources (only what is the page's own: title, styles, body)
│   ├── partials/         blocks shared by many pages: script lists, the step top bar, YOUR TURN, the next
│   │                     arrow, I'M COMMITTED
│   └── content-head.js   the frame of assets/core/content.js, where every step.js is gathered
├── html/          the app as served, built from src/ (never edit by hand: the unit tests check it matches)
├── assets/
│   ├── core/             no screen of its own: progress.js (course rules), store.js (all saved data),
│   │                     content.js (built from every step.js), steps.js (the step catalogue and blocks, from
```

## How the code is organised

- **A step is one folder**, `src/steps/stepNN/`: `learn.html` and `act.html` are its two pages, `step.js` the rest of what makes the step (each field is explained at the top of `src/content-head.js`). To change Step 16, open `src/steps/step16/`, edit, then run `node tools/build.js`.
- **Pages are built.** Each page's source (`src/pages/`, or the step folder) holds only its own content; `tools/build.js` adds the head lines every page shares (Home Screen tags and icon) and the version stamp (`?v=…` on every script and stylesheet, set once in `tools/build.js`), and fills in shared blocks (`<!--#scripts-step screen="act"-->` takes `src/partials/scripts-step.html`). Change a source, run `node tools/build.js`, and commit both. Netlify serves `html/` as it is: no build step there.
- **A screen is one file** in `assets/screens/`. It registers itself (`MirrorScreens.act = …`) and its page's shell runs it with what it needs: `assets/shell/step.js` for the step screens (it opens the right step, keeps the step bar, fits the titles), `assets/shell/app.js` for My Path, My Mirror and My Journey (links, tabs, saving before leaving). Pages like the block summary and the result run on their own.
- **Adding a screen:** write `assets/screens/name.js`, give its page a source in `src/pages/` that loads it (with the core files and, if it's a tab page or a step screen, the shared script list), run `node tools/build.js`, then add it to the visual baseline's list in `tests/visual-baseline.cjs`.
- **Saved data** only through `assets/core/store.js` (see **Saved data** below).

## Clickable preview

Open `index.html` in a browser, ideally through a local server such as VS Code Live Server so progress persists.

Opening the link goes straight to the Offer page. The preview connects Offer → My Path (map) → Step 01: Watch → Learn → Act → My Path → Step 02: Check in → Watch → Learn → Act → …

## Home Screen app (iPhone)

Every page carries the app manifest (`manifest.webmanifest`) and Apple's web-app tags, so "Add to Home Screen" from Safari gives a **Mirror 21** icon (black square, gold "21", `assets/icons/`) that opens full screen with no Safari bars. The status bar stays white with dark text. Screens keep clear of the clock and the home indicator using the phone's safe areas. Links to other websites (Stripe later) open Safari on top.

iPhones read these settings only when the icon is added: after a deploy that changes them, delete the old icon and add it again.
## Steps

The course is 21 **Steps** (previously "days"), plus **Step 00 · Welcome**. Step 01 is Watch → Learn → Act, built from the Step 01 design handoff (no longer kept in the project; its styles and fonts were copied into `assets/step/`). From Step 02, every step opens with a **Check in** on the previous step, built from the Step 02 check-in design handoff (also copied into `assets/step/`). The app changes these things from the handoffs, by agreement:

- there is **no sound button**;
- with no commit time saved (steps committed before `committedAt` existed), the check-in says "Last time you promised:";
- the Done text reads "Step 0N is open. It starts by asking how your step went."

**Step bar:** every step screen shows the handoff's part bar. Step 01 has 3 parts (Watch · Learn · Act); from Step 02 there are 4 (Check in · Watch · Learn · Act). Check in fills once answered, Watch once the video is watched, Learn as the reader scrolls and Act stage by stage (`segments` in `assets/core/progress.js`). Each part has its name underneath: gold once done, black for the screen you're on (white on Watch), grey still to come. The handoffs' section chip (icon square + CHECK IN / LEARN / ACT) is removed on every step: the labels replace it. The map's ring still uses the overall share (`session`).

Titles come from each step's `src/steps/stepNN/step.js` (block names are not shown yet). A title that is too long for one line shrinks just enough to fit. On the Watch screen (21px) at 390px wide, that is Step 04 (20.4px) and Step 06 (20.6px).

**Content so far:** all 21 steps have their own lessons (Step 02 from the Step 02 design handoff, likewise copied into `assets/step/step02.css`; Steps 03–21 from Step 03's layout, in the Step 02 components plus `assets/step/step03.css`), then the final check and the result page. Steps 01–21 play their portrait videos (`Audio-Video/StepNN-Watch.mp4`: 720×1280 H.264/AAC, saved with "faststart" so playback begins before the whole file loads; 1:45, 1:18, 1:18, 1:25, 1:38, 1:13, 1:20, 1:27, 1:30, 1:27, 1:35, 1:29, 1:27, 1:31, 1:20, 1:23, 1:26, 1:28, 1:28, 1:22, 1:24; Step 07 opens on a white flash, so its start image is taken at 0.5s, and Step 09 opens with red guide lines for its first 5 seconds, so its start image is taken at 5.5s). Each has its first frame as start image and its last frame as finish image (`assets/images/stepNN-start.jpg` / `-finish.jpg`), so nothing jumps; in the step's `src/steps/stepNN/step.js` a filmed step is one line, `watch: 'm:ss'`. Welcome shows Step 01's start image and "VIDEO COMING SOON" with an 8-second simulated playback. For each new video: portrait 720×1280 MP4, a URL-safe name (`StepNN-Watch.mp4`), `ffmpeg -i in.mp4 -c copy -movflags +faststart StepNN-Watch.mp4`, a first-second frame as its start image, and its last frame (`ffmpeg -sseof -0.3 -i StepNN-Watch.mp4 -update 1 -q:v 3 stepNN-finish.jpg`) as its finish image. `assets/core/steps.js` turns each step's `watch` into its Watch content ( video, start image, finish image, length, button label) and lesson (`lesson` / `page`). To add a video, set its `video` there (for example `'../Audio-Video/Step01-Watch.mp4'`): the placeholder goes away by itself and the length comes from the file.

## Course rules (`assets/core/progress.js`)

- **Today** = the first step not yet committed. Committing a step opens the next one straight away.
- After HOLD TO COMMIT (which saves `committedAt`), the step's map tile is **committed**: plain white, gold number, no ring. The check-in at the start of the next step then gives it the look of the answer's icon: YES full gold, PARTLY half gold, NO gold ring only. Tapping a done tile shows its card with REDO STEP, which reopens it from Watch to rewatch, reread and see the (locked) Act answers. My Mirror rows open the same way. Redoing never changes the step's check-in or the step that is open now.
- Step 21's promise is graded by the final check (`html/final-check.html`), since there is no Step 22.
- **Points** = YES 1, PARTLY 0.5, NO 0, out of 21. Saved NOT YET answers from the first Step 02 design read as NO. Follow-through = points ÷ check-ins, rounded; 0% before any check-ins. Step 21 and the result page show it to one decimal (82.5%), over Steps 01–20 and all 21 respectively (`score` in `assets/core/progress.js`).
- **No time limit.** The course runs until all 21 promises are graded. My Path's header card and My Mirror's third ring count **steps to go** (21 minus committed steps; 19 after Step 02), not days.
- **My Mirror** shows:
  - STEPS SO FAR: the dots per block, with no count.
  - Three rings: FOLLOW-THROUGH, TO GO (steps left) and **MISSED**. MISSED counts the NO answers ("2 / OF 14" check-ins so far), and its ring is dark grey rather than gold.

  - **WORTH A SECOND LOOK:** the latest step answered NO, or the latest PARTLY if nothing was missed, tagged MISSED / PARTLY. It shows the step's circle, title and locked promise (two lines at most, then "…"), and REVISIT STEP NN, which reopens that step from Watch like a done step on the map. ## Saved data (`assets/core/store.js`)

Every read and write of saved data goes through `MirrorStore`: no screen touches `localStorage` or `sessionStorage` itself. It keeps two kinds apart, because they will live in different places once accounts exist:

| Kind | What | Today | With accounts |
|---|---|---|---|
| `MirrorStore.course` | the course (`mirror21-progress`), finished runs (`mirror21-runs`), the reminder time (`mirror21-reminder`) | this browser | the learner's account (Supabase), on any phone |
| `MirrorStore.device` | where the step bar stood (`mirror21-bar-N`), Welcome watched or left (`mirror21-watched-0`, `mirror21-seen-0`), block summaries opened (`mirror21-block-N`), the step still to be shown opening on My Path (`mirror21-unlock`), the one-time arrival note for Watch (`mirror21-intro`, session) | this browser | still this browser |

Each screen starts with `MirrorStore.ready(…)`, which runs it once the saved course is available: straight away today, and after the account's course has loaded once Supabase is connected. `course.load()` always gives a safe course (a fresh one when nothing valid is saved), `course.save(state)` stamps the time, `course.clear()` is Start over (and a new run), `deleteAll()` is Delete my data, and `course.onChange(fn)` reports a save from another tab. The keys and format are unchanged, so saved progress keeps working. The one exception to "only through the store" is the tiny script in `step-watch.html`'s head, which reads the arrival note before the first paint.

## Deploying on Netlify

Publish this folder as the site root, including `index.html`, `html/`, `assets/`, `Audio-Video/` and `_headers`. No build command is needed. `_headers` tells browsers to revalidate site files. Netlify Pretty URLs are supported (`/html/step-watch` and `/html/step-watch.html` are the same page). After deploying, check that `/Audio-Video/Step01-Watch.mp4` plays on the published site.

## Restart this device's session

Open `/html/restart-session` on the device you want to reset. It clears only Mirror 21 course state, bar positions, the Welcome watched flag and scroll positions from that browser, keeps reminder preferences, and opens Step 00 Welcome. Deploying an update by itself does not reset anyone's progress.
